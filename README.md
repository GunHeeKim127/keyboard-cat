# Keyboard Cat 1.3.16

키보드 입력 횟수에 반응하는 Windows/macOS 데스크톱 반려동물입니다. 기존 고양이와 치와와·진돗개·리트리버·시바견·허스키 중 하나를 리모컨에서 마우스로 선택합니다. 현재 버전은 **1.3.16 · 샴 보행 안정화·Windows 설치형 업데이트**입니다. 이름 숨기기를 리모컨 첫 화면의 버튼으로 바로 선택할 수 있습니다.

## v1.3.16 샴 보행·설치형 업데이트

- 샴 보행만 얼굴 방향·목/몸통 비율이 프레임마다 달라 보이는 부분을 보정했습니다. 다른 모션·품종 PNG 434개와 재생 속도·이동 간격은 유지합니다. 원본: `assets/cats/siamese-walk-v8-sheet.png`.
- Windows 설치형은 업데이트 확인 → 다운로드 진행률 → **설치하고 다시 시작**을 제공합니다. 새 설치본으로 기존 설치본을 교체하며 설정은 유지합니다. 처음 한 번은 이 버전의 설치형으로 설치해야 합니다. 휴대용 EXE·미설치 개발본·Mac은 다운로드 후 직접 교체합니다. Mac 유료 서명은 보류합니다.
- 자동 적용에는 같은 정식 GitHub Release에 생성된 `latest.yml`과 이름을 바꾸지 않은 `Keyboard-Cat-<버전>-setup.exe`가 함께 있어야 합니다. 버전·이름·SHA-512 정보가 없거나 맞지 않으면 설치하지 않습니다. Actions artifact나 태그만 올리는 것은 정식 Release가 아닙니다.
- 앱을 그냥 종료할 때 임의로 설치하지 않으며, 사용자가 설치 버튼을 눌러야 합니다. 새 버전 설치 전 기존 앱을 먼저 삭제하지 않습니다. 임의 다운로드 폴더나 다른 앱은 삭제하지 않습니다. Mac은 응용 프로그램 폴더에서 대치 후 새 앱을 확인하고 이전 DMG를 휴지통에 넣으세요.
- 자세한 준비·제한·검증은 [UPDATE-INSTALL.md](UPDATE-INSTALL.md)에 있습니다.

- Windows 최신 파일은 `release/windows-1.3.15/`, Mac은 같은 커밋의 Actions 결과물을 사용합니다. 최적화 범위와 검증은 [OPTIMIZATION-REVIEW.md](OPTIMIZATION-REVIEW.md)에 기록합니다.

## v1.3.14 보행 비율 보정

- v1.3.13에서 걷기는 부드러워졌으나 기존 모션보다 다리가 길고 몸통이 얇아 보이던 차이를 수정했습니다. 고양이 5품종·강아지 5종의 80자세 전체를 다시 그려 다리를 짧고 도톰하게, 몸통과 배를 둥글게 맞췄습니다. 전체 그림을 눌러 늘이거나 다리를 잘라 조립하지 않습니다.
- 얼굴·품종별 특징·보행 순서·8프레임을 유지하며, 대기·점프·착지와 수정 전후 보행을 나란히 비교했습니다. 수정 후 전체 프레임에서도 크기·머리 위치·발끝 구분·여백·반복 연결을 다시 점검합니다.
- 원본은 `assets/{cats,dogs}/*-walk-v7-sheet.png`입니다. `node scripts/review-proportions.cjs`로 v1.3.13 보행과 기존 모션을 함께 비교할 수 있습니다. 그 외 모션·설정·업데이트 확인·Mac 입력 복구 기능은 그대로입니다.
- Windows는 `release/windows-1.3.14/`의 휴대용·설치형 파일을 사용하세요. 리모컨에 v1.3.14가 표시되어야 합니다. Mac은 최신 커밋에 대한 Actions 빌드의 AppleSilicon(M1 Pro 포함) 또는 Intel 파일을 선택하세요. 실제 Mac 권한·물리 입력은 별도 확인 대상입니다.
- 검증 순서: 이미지 수정 → 기존 모션·80프레임 비교 → 로컬 Electron 60초 반복 재생·교차 확인 → 보안 점검 → 최종 패키지 생성입니다. 실제 렌더러에서 10품종의 8프레임·양방향·정지·착지를 확인했고, 전체 76개 테스트·타입·빌드·CJS 구문 검사를 통과했습니다. npm의 알려진 취약점은 0건입니다. [보행 검토](WALK-REVIEW.md)와 [보안 점검](SECURITY-REVIEW.md)에 범위·한계를 기록했습니다.
- 최종 패키지 목록에서도 과거 16프레임 설정 잔재를 확인해 제거했습니다. Electron 포함 파일은 현재 사용하는 컴파일 JS로 제한하며, 예전 보행 설정·8~15 프레임이 들어가지 않았는지 재검사합니다.

- 보행 표시와 프레임 제작을 v1.3.9 방식으로 되돌렸습니다. v1.3.10~12의 몸통·다리 분리 자산, 관절·메쉬 변형 코드와 16프레임 보행은 제거했습니다. 이미 게시한 태그를 덮어쓰지 않도록 새 패키지 번호는 1.3.13입니다.
- 새 고양이 5품종과 강아지 5종은 각 자세마다 동물 전체가 그려진 새 8프레임 이미지를 사용합니다. 앞발의 앞쪽 디딤·몸 아래 지지·뒤쪽 지지·낮은 되돌림과 반대쪽 발이 구분되도록 시안을 반복 수정했습니다. 네 다리를 앱이나 빌드 과정에서 따로 조립하거나 변형하지 않습니다.
- 얼굴 정렬·기존 크기 제한·투명 여백·원본 가로세로 비율을 유지합니다. Original, 보행 외 모션, 목덜미 들기, 사다리, 콤보, 리모컨 스위치·이름 표시, Mac 입력 복구는 보존합니다.
- 제작 기록: [전체 이미지 보행](assets/WHOLE-WALK-GENERATION.md). `node scripts/preview-motions.cjs`로 GIF와 전체 동작 비교 그림을, `node scripts/review-walks.cjs`로 80프레임 비교 그림과 반복 연결 수치를 다시 만들 수 있습니다. 수치는 자연스러움을 증명하지 않으므로 이미지도 함께 검토합니다.
- 새 버전 확인·변경 내용·플랫폼별 다운로드 버튼은 유지했습니다. **현재 다운로드 버튼은 브라우저 다운로드이며 자동 덮어쓰기·설치·재시작은 아직 구현되지 않았습니다.** 이 기능을 자동 설치 완료로 안내하지 않습니다. 유료 서명·공증 및 새 GitHub Release 게시는 보류 상태입니다.
- Windows 패키지: `release/windows-1.3.13/Keyboard Cat 1.3.13.exe`와 `Keyboard Cat Setup 1.3.13.exe`. 리모컨 버전이 1.3.13인지 확인하세요. Mac은 아래 Actions에서 최신 커밋의 성공한 빌드와 버전을 확인하세요. 실제 Mac 권한·물리 키 입력은 Windows 환경에서 검증할 수 없습니다.
- 검증: 타입 검사·빌드·76개 회귀 테스트·변경한 CJS 구문 검사·Windows 패키지 실행 검사를 통과했습니다. Original 및 보행 외 PNG 353개가 v1.3.9와 동일하고 업데이트·Mac 입력 코드가 v1.3.11과 동일함을 별도로 비교했습니다. 패키지 내부 버전·주요 코드와 최신 소스의 일치도 확인했습니다. 별도 린트 도구는 설정되어 있지 않습니다. 검토 기록은 [WALK-REVIEW.md](WALK-REVIEW.md)에 있습니다.

## v1.3.12 사족 보행 재수정 (이력: 보행 구현은 v1.3.13에서 제거)

- 기존 보행에서 뒷발의 위상이 뒤바뀌어 앞·뒷발의 디딤 순서가 어색했던 부분을 수정했습니다. 한쪽 뒷발 → 같은 쪽 앞발 → 반대쪽 뒷발 → 반대쪽 앞발의 4박자 걷기를 사용합니다. 실제 고양이·강아지 보행 연구를 참고했습니다: [고양이 디딤 순서](https://pmc.ncbi.nlm.nih.gov/articles/PMC4044364/), [강아지 보행 운동학](https://pmc.ncbi.nlm.nih.gov/articles/PMC4517757/).
- 다리를 통째로 기울이고 줄이는 대신 길이가 일정한 관절 구조를 적용했습니다. 앞다리 팔꿈치와 뒷다리 무릎은 서로 다른 방향으로 접히고, 발은 낮게 지나가며 디딘 동안에는 바닥 높이와 발바닥 방향을 유지합니다. 관절 주위의 이미지는 이어지는 메쉬로 변형해 분절 사이의 틈을 줄입니다.
- 캐릭터 전체를 흔들어 디딘 발까지 움직이던 효과를 제거했습니다. 작은 체중 이동은 몸통과 다리 뿌리에만 적용하며 발은 바닥에 유지합니다. 머리·몸통의 크기는 고정합니다.
- 새 고양이·강아지의 화면 이동 속도를 보폭·보행 주기·표시 크기에 맞췄습니다. 기존의 한 번에 3px 이동 대신 남은 거리를 누적해 정수 좌표로 조금씩 이동합니다. 따라서 이전보다 천천히 걷습니다. Original의 기존 이동 속도와 이미지·보행은 유지합니다.
- 보행 자산은 기존 품종 얼굴·색·체형을 보존합니다. 전체 재생성 이미지 시안도 비교했지만 디딤 순서를 따르지 않아 채택하지 않았습니다. 다른 모션·사다리·목덜미 들기·콤보·설정·업데이트·Mac 권한 복구 기능은 유지합니다.
- 디딤 순서, 뼈 길이, 접지 높이·발바닥 방향, 보폭과 이동 속도의 일치, 크기·테두리와 기존 기능을 검사합니다. Mac 실기기에서의 권한·물리 입력은 별도 확인 대상입니다.
- 타입 검사·구문 검사·빌드·81개 회귀 테스트를 통과했습니다. 별도 린트 도구는 프로젝트에 설정되어 있지 않습니다. Windows 실행 검사와 Mac 자동 빌드도 새 버전 기준으로 확인합니다.

## v1.3.11 Mac 권한 재연결 보완

- Windows와 macOS 모두 리모컨에서 업데이트 확인·변경 내용 보기·버전에 맞는 파일 다운로드를 지원합니다. 파일을 받은 뒤 기존 앱을 종료하고 교체합니다. 자동 설치는 하지 않습니다.
- Mac 입력 보조 프로그램이 준비 응답 없이 멈추면 30초 뒤 종료하고 5초 뒤 새 프로세스로 다시 연결합니다. 재연결에서는 권한 팝업을 반복해서 요청하지 않습니다. 이미 준비된 보조 프로그램이 예기치 않게 정상 종료된 경우도 복구합니다.

다섯 견종마다 기존 24개 포즈와 새 8프레임 걷기를 사용합니다. 대기·걷기·점프·낙하·착지·대시·놀이(ATTACK)·수면·들기·사다리에 연결하며 사다리 내려오기는 해당 프레임을 역순으로 재생합니다. 견종 특징은 귀여운 시각적 해석입니다. 기존 고양이 원본·아틀라스·들기 이미지는 보존합니다.

## 리모컨 기능과 켜기·끄기

기존의 **자동 이동, 콤보 특수 효과, 대기 애니메이션, 수면 애니메이션, 콤보 숫자 표시, 마우스로 집어 들기, 다중 모니터 이동** 일곱 스위치를 모두 유지합니다. 고양이와 강아지에 동일하게 적용됩니다. 크기·FPS·위치 초기화·입력 다시 연결·일시정지·리모컨 숨기기·앱 종료도 유지합니다.

| 품질 | 크기 | 재생 속도 | 자동 이동 | 특수 효과 | 대기 반복 | 수면 반복 |
| --- | --- | --- | --- | --- | --- | --- |
| 저 · 기본 | 75% | 5 FPS | 끔 | 끔 | 끔 | 끔 |
| 중 | 100% | 8 FPS | 끔 | 켬 | 끔 | 켬 |
| 고 | 130% | 12 FPS | 켬 | 켬 | 켬 | 켬 |

- 기능은 개별 조정할 수 있으며 성능 관련 값을 바꾸면 사용자 설정으로 표시됩니다. 수면 반복은 별도로 켤 수 있습니다. 고양이는 2.5 FPS, 강아지는 한 포즈를 최소 1.2초씩 유지합니다. 꺼도 정지된 수면 자세는 표시합니다.
- 다중 모니터 이동을 끄면 주 모니터로 제한합니다. 다시 켜면 다른 모니터로 이동할 수 있으며 여러 마리로 복제하는 기능은 아닙니다.
- 마우스로 집어 들기를 켜면 반려동물 영역만 클릭을 받고 주변 투명 영역은 통과합니다. 끄면 클릭을 통과시킵니다. 위치 조정 모드에서는 드래그로 이동합니다.
- 아바타 이름은 최대 20자이며 고양이와 강아지가 공유합니다. 리모컨 위쪽의 **이름 표시**에서 **항상 / 마우스를 올릴 때만 / 숨기기** 버튼을 누릅니다. 기본값은 기존처럼 마우스를 올릴 때만 표시이며, 표시 방식은 재실행·성능 프리셋 변경 후에도 유지됩니다. 숨기기를 선택해도 이름 자체는 삭제되지 않습니다.
- 리모컨을 숨겨도 반려동물은 계속 표시됩니다. 트레이 아이콘을 더블클릭하거나 실행 파일을 다시 실행하면 리모컨을 엽니다.
- 일시정지는 입력 보조 프로그램과 재시도를 중지하고 콤보를 초기화합니다.

## 입력과 콤보

1.5초 미만 간격으로 키를 누르면 콤보가 이어집니다. 콤보 특수 효과를 켰을 때 아래 배수마다 반복합니다. 저품질 기본값은 효과 끔이므로 필요하면 리모컨에서 켜세요.

| 콤보 | 모션 |
| --- | --- |
| 10의 배수 | 점프 → 낙하 → 착지 |
| 20의 배수 | 사다리 오르기 → 내려오기 → 착지 |
| 30의 배수 | 대시 |
| 50의 배수 | 고양이 공격 / 강아지의 놀이·앞발 모션 |

겹치면 50 공격/놀이 → 30 대시 → 20 사다리 → 10 점프 순서입니다. 40은 사다리, 60은 대시, 100·150은 공격/놀이입니다. 사다리는 제자리 애니메이션이며 창을 위아래로 옮기지 않습니다. 입력이 없으면 약 4초 후 걷기, 30초 후 수면으로 전환합니다. 점프·대시를 Space/Shift에 연결하지 않으며 키 종류와 관계없이 기존 횟수 방식으로 반응합니다.

## 개인정보와 보안

Windows는 전역 키보드 훅 대신 Raw Input 알림을 받고, macOS는 읽기 전용 CoreGraphics 이벤트 탭을 사용합니다. 최종본은 키 코드·문자·키 이름·창 제목을 읽거나 기록하지 않고 누름 횟수만 처리합니다. 다른 앱 입력을 억제하지 않습니다. 입력 횟수와 내용은 파일에 저장하거나 외부로 전송하지 않습니다. 저장하는 것은 위치·이름·반려동물·견종과 사용자 옵션입니다.

설정은 Windows의 `%APPDATA%/keyboard-cat/settings.json`, Mac의 `~/Library/Application Support/keyboard-cat/settings.json`에 있습니다. 리모컨의 입력 진단은 요청할 때만 실행 위치, 고정 오류 코드, 흔한 위치의 앱 복사본과 설정·캐시 경로를 읽기 전용으로 확인합니다. 진단 복사에는 경로의 사용자 이름이 포함될 수 있으니 공유 전 확인하세요. 권한 DB·다른 앱·사용자 설정은 자동 삭제하거나 초기화하지 않습니다.

Electron contextIsolation·sandbox·Node 접근 차단, IPC 창/최상위 프레임/문서/자료형 검증, 로컬 리소스 허용 목록, CSP, 웹 권한·다운로드·탐색 차단을 유지합니다. 설정 파일은 최대 64KiB만 읽고 이름은 HTML이 아닌 텍스트로 표시합니다. 견종·반려동물 값도 허용 목록으로 검증합니다. 2026-10-20 npm 감사에서 9개 취약점을 의존성 수정 후 0개로 줄였으며 1.3.16에는 Windows 설치형 업데이트를 위한 electron-updater 6.8.9를 추가했으며 전체 의존성 재감사도 0건입니다. npm에 앱을 게시하지 않았습니다.

## Mac 설치·실행·업그레이드 빠른 매뉴얼

자세한 화면 순서·재설치·진단은 [MACOS.md](MACOS.md)에 있습니다. 일반 사용자는 Node.js/Xcode/npm 설치나 터미널 설정 없이 설치본을 사용합니다.

| Mac 종류 | 받을 파일 |
| --- | --- |
| M1·**M1 Pro**·M1 Max·M1 Ultra 및 M2/M3/M4/M5 계열 | **Apple Silicon / arm64.dmg** |
| Intel 프로세서 | **Intel / x64.dmg** |

### 처음 설치하고 여는 순서

1. 위 Mac 링크에서 내 CPU용 Artifacts ZIP을 받아 압축을 풀고 DMG를 엽니다.
2. **Keyboard Cat.app을 응용 프로그램(Applications)으로 드래그**합니다. 최종 설치 경로는 `/Applications/Keyboard Cat.app`입니다.
3. 복사가 끝나면 Finder에서 DMG를 꺼냅니다. **Finder → 응용 프로그램 → Keyboard Cat.app**을 더블클릭해 실행합니다. DMG 안의 앱이나 예전 다운로드 복사본을 열지 않습니다.
4. 개발자 확인 알림이 나오면 다운로드 출처·앱 이름을 확인하고 **시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기(Open Anyway)**에서 이 앱의 실행 예외를 선택합니다. [Apple의 앱 열기 안내](https://support.apple.com/102445)
5. 리모컨의 **입력 모니터링 권한 설정** → **개인정보 보호 및 보안 → 입력 모니터링**에서 **현재 Applications의 Keyboard Cat**을 허용합니다. 목록에 없으면 +로 앱을 추가합니다. 이 권한과 앱 실행 허용은 서로 다릅니다. [Apple 입력 모니터링 안내](https://support.apple.com/guide/mac-help/mchl4cedafb6/mac)
6. 리모컨의 **앱 종료**나 메뉴 막대 아이콘 메뉴의 **종료**로 완전히 종료한 뒤 같은 Finder 경로에서 다시 실행합니다. 리모컨 숨기기는 종료가 아닙니다. 준비 완료와 일반 편집기에서 실제 타이핑을 확인합니다.
7. 리모컨은 메뉴 막대 아이콘의 **리모컨 열기**로 다시 엽니다. 이름은 **항상 표시 / 마우스를 올릴 때만 표시 / 숨기기**에서 고를 수 있습니다.

### 새 버전을 받았을 때

**보통은 전부 지우지 않습니다.** 기존 앱 종료 → 새 DMG의 앱을 Applications에 **대치/교체** → DMG 꺼내기 → Finder의 Applications에서 실행 → 버전과 수정 빌드 문구 확인 순서입니다. 이름·견종·표시 옵션은 유지됩니다. 입력이 정상이면 터미널 명령 없이 끝납니다. 정상 동작을 확인한 뒤 필요 없는 이전 다운로드만 정리합니다.

### 권한을 켰는데도 안 될 때 실행할 명령

먼저 리모컨의 **입력 진단 · 이전 앱 확인**에서 실제 실행 위치가 Applications인지 확인합니다. 입력 모니터링의 Keyboard Cat 항목만 제거하고 현재 설치본을 다시 추가·허용한 뒤 완전히 종료·재실행합니다. 그래도 실패할 때만 **앱을 종료한 상태에서** Mac의 터미널에 아래 전체를 **한 줄로** 넣습니다.

```sh
tccutil reset ListenEvent local.keyboardcat.pet
```

`local.keyboardcat.pet`만 따로 실행하는 것이 아닙니다. 이는 앱의 입력 권한을 **초기화**하며 허용하지는 않습니다. 이어서 **Finder → 응용 프로그램 → Keyboard Cat.app** 실행 → 입력 모니터링에서 현재 앱 허용 → 앱 완전 종료·재실행 → 실제 입력 확인을 진행합니다. 이름·견종 설정은 이 명령으로 삭제되지 않습니다. 오류가 나오면 메시지를 확인하고 전체 앱 권한 초기화나 권한 DB 삭제로 확대하지 않습니다. [Apple의 앱별 권한 초기화 설명](https://developer.apple.com/documentation/xcode/resetting-access-to-protected-resources-in-macos)

### 완전히 지우고 다시 설치하려는 경우

앱을 완전히 종료하고 Applications의 **Keyboard Cat.app만** 휴지통으로 옮깁니다. 이름·견종·위치까지 초기화하려는 경우에만 Finder의 **이동 → 폴더로 이동(⇧⌘G)**에서 `~/Library/Application Support/keyboard-cat`을 찾아 삭제 대신 별도 폴더로 **백업 이동**하세요. 존재할 수 있는 앱 전용 캐시·환경설정·이전 앱 복사본과 원상 복구 방법은 [MACOS.md의 새로 설치 절차](MACOS.md#7-완전히-새로-설치하고-싶을-때-백업-후-앱-전용-데이터만)를 따릅니다. 상위 Library 폴더나 프로젝트 파일은 지우지 않습니다.

새 파일 다운로드 → Applications 설치 → Finder 실행 → 입력 권한 허용 → 완전 종료·재실행으로 확인합니다. 앱·설정을 지워도 macOS 권한 기록은 따로 남을 수 있습니다. 권한 문제가 남을 때만 위 tccutil 명령을 적용합니다. 재설치가 모든 Mac 권한 오류를 해결한다고 보장하지 않으며 실제 물리 입력 확인이 필요합니다.

## 개발과 검증

Node.js 22.12 이상(24 권장), npm, Windows 기본 .NET Framework 4.x 또는 Mac Xcode Command Line Tools가 필요합니다. 현재 검증은 Node 24를 사용합니다.

```sh
npm ci
npm run build
npm test
npm start
npm run dist:win
# Mac에서:
npm run dist:mac
```

현재 Windows 출력 폴더를 그대로 재현하려면 빌드 후 다음 명령을 사용합니다. 기존 파일 정리 스크립트는 호출하지 않습니다.

```sh
npx --no-install electron-builder --win nsis portable --publish never --config.directories.output=release/windows-1.3.6
```

`npm run dev`는 빌드 후 실행하며 `npm run sprites`는 고양이 프레임과 강아지 아틀라스를 다시 만듭니다. 새 이미지 생성은 빌드에 포함되지 않으며 저장된 원본 PNG만 사용합니다. 설치 파일 생성은 --publish never이며 Git 커밋·푸시를 자동 수행하지 않습니다.

```sh
npx electron . --smoke-test
node scripts/check-native.cjs
```

현재 모션 수정본의 로컬 빌드·양쪽 TypeScript 검사·60개 테스트, Windows 네이티브 등록과 소스 앱/실제 패키지 실행 검사가 통과했습니다. Windows 휴대용/설치형 EXE 무결성과 검증한 앱 payload의 일치도 확인했습니다. 실제 리모컨에서 5종×11개 상태 로딩·선택 저장·고양이 복귀·기존 일곱 토글 각각의 켜기/끄기, 기존 좌표·집기·IPC/웹 보안도 검사합니다. 스모크 검사는 임시 설정을 쓰며 실제 물리 입력을 켜지 않습니다. 별도 lint 명령은 설정되어 있지 않습니다.

Mac에서는 4355c1a의 [최신 성공한 빌드](https://github.com/GunHeeKim127/keyboard-cat/actions/runs/39439641219)에서 컴파일·60개 테스트·두 아키텍처 helper·DMG/ZIP·번들/압축 검증과 산출물 업로드가 성공했습니다. 실제 Mac 물리 키 입력과 TCC 승인, 실제 다중 모니터·Spaces·절전 복귀는 사용자 기기에서 확인해야 합니다. 합성 입력을 물리 키 테스트로 취급하지 않습니다. 유료 서명·공증·새 Release 게시는 하지 않았습니다.

## 소스와 이미지 위치

- `electron/`: 창·IPC·옵션·콤보·좌표·진단·반려동물 허용 목록.
- `src/`: 고양이·강아지 표시와 리모컨 UI.
- `native/`: Windows Raw Input과 Mac 읽기 전용 횟수 감지.
- `scripts/`: 빌드·고양이 프레임 추출·강아지 아틀라스 패킹·패키지 검증.
- `tests/`: 콤보·좌표·옵션·보안·입력 수명·배포와 강아지 리소스 회귀 검사.
- `public/sprites/`: 기존 고양이 아틀라스 9개와 carry.png, 강아지 아틀라스 50개와 런타임용 dog-<견종>-<상태>-frame-<번호>.png 140개. 런타임 파일은 동일한 평면 리소스 허용 목록 안에 있습니다.
- `assets/dogs/`: 새로 생성한 다섯 원본 시트. 내장 imagegen 도구를 사용했으며 프롬프트와 4×6 셀 구성은 [GENERATION.md](assets/dogs/GENERATION.md)에 보관합니다. 별도 유료 API 호출이나 외부 스프라이트 다운로드는 하지 않았습니다.
- `CHANGELOG.md`: 최근 수정 빌드별 상세 변경 기록.

참고: [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window), [Microsoft Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input), [Apple 입력 권한 초기화](https://developer.apple.com/documentation/xcode/resetting-access-to-protected-resources-in-macos).
